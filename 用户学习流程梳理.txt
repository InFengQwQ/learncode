编程语言学习平台 — 用户完整学习流程（必经路径）
====================================================

一、添加语言
    用户输入语言名
    → Wikipedia 搜索验证（Go 层信号评分，非语言直接拒绝）
    → LLM 分类判定：确认 is_language，判定兼容模式（多版本并存 / 向后兼容 / 无版本区分）
    → LLM 查找最新稳定版本：版本号 + 环境来源（dockerhub / 官网下载页 / 包管理器），全部需确认有效
    → 用户确认，创建 Language 记录
    → 创建后自动递归拓展：逐个取得该语言所有受支持的历史版本（每个版本：版本号 + 环境来源），直到全部覆盖

二、容器运行时构建
    依据每个 Version 的环境来源直接构建隔离容器
    → 验证容器可用（版本号匹配、包管理器正常、可执行基本代码）
    → 标记 Version 为就绪状态

三、知识库构建（小型语言 wiki）
    针对每个 Version 独立构建：
    ├── 官方语法文档（爬取官方文档 + LLM 结构化提取，含代码示例）
    ├── 标准库文档（按模块/包组织，含高频 API 用法）
    └── 编程规范与最佳实践（官方 style guide + 社区共识）
    知识库以可浏览的层级结构在前端展示（LanguageDetailPage 内），用户可见。
    同步存入数据库，供 LLM 在出题和判题时检索（后期接入 embedding/rerank 模型提升检索精度）。
    同语言多版本之间，部分知识库条目可跨版本共享，不必重复构建。

四、练习循环（核心学习机制）
    1. 系统根据用户在当前语言/版本下的学习进度，由 LLM 生成一个练习项目：
       - 需求文档（用户可见，描述要实现的功能和行为）
       - 参考答案（用户不可见）
       - 验证脚本（用户不可见，自动化判题）
       第一步，LLM 必须确认验证脚本对需求文档的覆盖是充分且正确的。
       第二步，LLM 必须确认参考答案可以跑通验证脚本，否则修改参考答案。
    2. 用户在本地 IDE 中按需求文档编写代码。
    3. 用户提交代码目录到系统。
    4. 系统在对应 Version 的隔离容器中运行验证脚本：
       - 通过 → 项目自动纳入用户项目库
       - 失败 → 返回验证输出，用户修改后重新提交
    5. 后续出题时，LLM 将用户项目库中的已有项目作为学习背景参考：
       - 避免重复出题
       - 逐步提升难度
       - 新题可建立在旧项目的基础上扩展
    整个系统不存在预置题库，所有练习均为实时生成、用完即走的一次性产物。

五、用户画像与进度
    ├── 以 Language 为单元计算学习进度
    ├── 同语言多个版本之间：部分进度共通（如语法基础），部分知识库共享
    └── 个人项目库可按语言/版本浏览，记录所有通过的练习
